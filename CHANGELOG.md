# Changelog

## Unreleased

## 0.1.1
- Documentation deploys from `main` only, since the `github-pages` environment rejects tag refs.
- Installer downloads fall back to `curl` when Python fails TLS verification or times out.
- Fixed a broken documentation link that failed the docs build.

## 0.1.0
- `import metatraderx as mt5` for Windows, Linux and macOS, with a local terminal backend (official package on Windows, an automatic Wine worker on Linux and macOS) and a remote backend for `mtx serve`.
- Added the `mtx` command: install, download, setup, terminal, login, info, symbols, symbol, fetch, serve, display, cache, config, mt4 and doctor.
- Added optional SQLite caching (`MTX_CACHE`) and offline mode (`import metatraderx.offline as mt5`, `MTX_OFFLINE`, `mtx --offline`) with `verbose` (bool or int, `MTX_VERBOSE`, `mtx -v`) notices.
- Added a read-only MetaTrader 4 bridge expert.
- Terminal search covers every drive on Windows and every Wine prefix with its mapped drives on Linux and macOS, plus `MTX_SEARCH` folders.
- `mtx symbols` lists names only by default, with `--first`, `--last` and `--full`.
- `mtx cache clear` asks for confirmation unless `-y` is given.
- `mtx display setup` installs Xpra, its HTML5 client and the other display requirements on Windows, Linux and macOS; `mtx display` offers it when something is missing.
- On Linux and macOS `initialize()` reports a missing `mtx setup` with a clear error (`SetupWarning`, or `SetupError` with `strict=True`) instead of a bare failure, and never falls back to cached data.
- Every public class, method and function has a docstring, and `__init__.pyi` / `offline.pyi` stubs (generated by `scripts/stubs.py`) give editors the signatures and docs of the module-level functions. Result records are typed `NamedTuple` classes with a description per field.
- Test suite covers the codec, cache, client, offline mode, server, remote, Wine and MT4 backends, discovery, installer, display and every `mtx` command.
- Documentation split into Python API, modes, server, display, command line, platforms, settings and troubleshooting, with the reference pages generated from the package.
- Added `mtx uninstall` and `metatraderx.uninstall` to remove a MetaTrader 4 or 5 terminal, including a broker's own build, with `--data`, `--prefix`, `--stop` and `--dry-run`.
- MetaTrader 4's `terminal.exe` is recognized as MetaTrader 4 and found after a headless install.
- Downloads are written to a `.part` file and renamed when complete, so an interrupted download is never reused.
- Headless Wine runs wait for, or stop, Wine's leftover processes before closing the virtual screen, which removes the "X connection broken" messages.
- `mtx setup` uses any Windows Python it finds in the Wine prefix, wherever it is installed, preferring one that already has MetaTrader5. When there is none, or MetaTrader5 cannot be installed into it, Python 3.12 is installed.
- `mtx install` on Linux installs headless by default: the Windows installer runs silently under Wine on a virtual screen, then the terminal it starts is stopped. `--method script` keeps the official MetaQuotes script.
- Added the `winedebug` setting (`MTX_WINEDEBUG`, `mtx --winedebug LEVEL`) with the levels `all`, `fixme` and `off`.
- `mtx display setup` adds the official xpra.org repository on Debian and Ubuntu and keeps it only when its packages install on the system; when xpra.org has no repository for the release (such as Ubuntu 25.04) or its packages do not fit, nearby releases are tried and a repository that does not fit is replaced.
- `mtx display` uses the first free port from 14500 when `--port` is not given, and reports a requested port that is in use.
- `mtx display` on Linux writes the terminal output to `logs/terminal.log` in the MetaTraderX home, refuses to start when the terminal is already running, and says where the log is when the terminal exits right away.
- Added `mtx display --force`, which closes a running terminal and anything else in its Wine prefix before the display starts, and `mtx serve` uses the first free port from 8765 when `--port` is not given.
- `mtx display` starts Xpra without an input method daemon, which stopped leaving `ibus-daemon` running after the display closed.
- Installer scripts and downloads run from and are saved in the MetaTraderX downloads folder instead of the current directory.
